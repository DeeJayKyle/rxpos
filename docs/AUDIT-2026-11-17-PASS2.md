## P2-7: the options (option 1 chosen on 17 Nov 2026)

A quick PIN or a fingerprint proves the person to **this device** only. The cloud never sees it, so it cannot issue a
token for them. The options:

1. **Recommended. Borrowed sign-in is marked, and only syncs.** When the device's token belongs to someone else, the
   session is marked as borrowed. The device keeps syncing so the till keeps working. Anything that acts as a person
   in the cloud (Users, sign-out-everywhere, two-step settings, report sending, owner messages) asks for the
   password first, which gives that person their own token. The cloud audit log notes "via <device>" for synced
   changes. Both apps.
2. **Password needed online.** A PIN or fingerprint works only when the device is offline. Online, the password is
   needed (the cloud then gives a token for that person). Simple, but staff type passwords more often.
3. **Device token.** Each till gets its own device sync key with a fixed, limited role, used for sync whoever is
   signed in. Personal tokens only come from a password. This is the cleanest, but it is the largest change (cloud,
   both apps, and moving existing tills over).

**Done (option 1):** each device remembers whose cloud token it holds (set at every password sign-in). Syncing,
selling, Mobile Money and SMS carry on whoever is signed in. A call that acts as a person (two-step sign-in, ending
sessions, the calendar and daily-stock links, sending a report or the day summary) first asks the person signed in
for their own password when the token is someone else's; the device then holds their token, so the call (and the
cloud's audit log) is theirs. A device from before keeps no token owner, so each person confirms once. A pharmacy sync
key belongs to no one and never asks.
