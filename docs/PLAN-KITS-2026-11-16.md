## Part 2 — Kits
✔ Design: **a kit is a recipe, not separate stock.** A `products` record with
`kit: { items: [{ productId, qty } | { service: true, name, price, cost? }], icon, color, warning, ack: bool, price? }`
and `active`. It has no movements of its own.

- Available = min over stock components of floor(stock ÷ qty) ("can make N"). Name the short component when 0.
- Cost = live sum of component cost × qty (+ service cost). Price = sum of component retail × qty (+ service
  price) unless a fixed kit price is set; show the margin.
- Earliest expiry, Rx and controlled flags are inherited from the components.
- Selling: one sale item for the kit (`items[i].kit = { components: [{ id, name, qty, cost, alloc }] }`), one "Sale"
  movement per component batch (FEFO via the existing `allocate`), in the same `update()` transaction as the sale
  (`POS.jsx` `finalize`, ~l.507–540). Stock stays the sum of movements, so offline sync is unchanged.
